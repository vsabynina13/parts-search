# Подбор автозапчастей и аналогов

Тестовое задание: React + Redux (Redux Toolkit) + Bootstrap, без TypeScript.
API: «Проценка» Favorit-parts (`GET http://api.favorit-parts.ru/hs/hsprice/`).

## Запуск

```bash
cp .env.example .env   # указать свой ключ в VITE_API_KEY
npm install
npm run dev
```

Тесты: `npm test`.

## Как работает

1. Пользователь вводит артикул. После паузы в 500 мс уходит запрос `?number=…`, предыдущий запрос отменяется.
   Из ответа строится список производителей.
2. По клику на производителя уходит запрос `?number=…&brand=…&analogues=on`.
   Таблица показывает искомую деталь и аналоги по складам: наименование, производитель, склад, дата отгрузки, цена, остаток.

## Решения

- **Один slice в Redux** (`src/store/searchSlice.js`), запросы через `createAsyncThunk`. Статусы `idle / loading / succeeded / failed`
  есть для каждого этапа. Ответы устаревших запросов отбрасываются по `requestId`, поэтому быстрый ввод не перезаписывает свежий результат.
- **Нормализация ответа** вынесена в чистые функции (`src/api/normalize.js`) и покрыта тестами:
  - ответ `{ error }` превращается в исключение;
  - пустой элемент, который API возвращает, когда «не найдено», отфильтровывается;
  - цена берётся со склада, потому что документация просит не использовать поле `price` товара.
- **Ошибки:** нет сети, HTTP-ошибка, ошибка API, пустой ответ. Для каждого случая показывается сообщение и кнопка «Повторить».
- **API работает по http**, поэтому в dev запросы идут через прокси Vite (`/api` → `api.favorit-parts.ru/hs/hsprice`).
  Так нет mixed content, если приложение открыто по https. В проде нужен такой же прокси на nginx или BFF,
  а ключ лучше подставлять на сервере, чтобы он не попадал в бандл.
